Анализ пользовательских отзывов

Система помогает службе поддержки разбирать отзывы о товарах и готовить ответы клиентам.

Вход: текст одного отзыва на русском языке.

Выход: JSON с полями sentiment (positive, negative, neutral или mixed), problems (список явно указанных проблем) и reply (короткий ответ клиенту). Если проблем нет, список пустой. Ответ не должен содержать выдуманные факты или обещания.

Пример входа: Товар хороший, но доставили на неделю позже.
Пример выхода: {"sentiment": "mixed", "problems": ["Доставка задержалась на неделю"], "reply": "Спасибо за отзыв. Рады, что товар понравился. Приносим извинения за задержку доставки."}

Первая операция LLM: определить тональность и извлечь проблемы из отзыва. Вторая операция LLM: составить ответ клиенту с учётом результата анализа.

Архитектура Sequential: отзыв > анализ > ответ клиенту > итоговый JSON. Второму этапу нужен результат первого, чтобы учитывать тональность и проблемы. Между этапами передаётся словарь с результатом анализа. One-shot выполняет обе операции одним запросом. Модель OpenRouter: nvidia/nemotron-3.5-super-vl:free.

Сценарии использования: подготовка ответов для оператора поддержки и выделение жалоб для дальнейшего разбора.

Дальнейшее развитие: обработка нескольких отзывов, группировка частых проблем и поиск правил поддержки в базе знаний.

Запуск: Python 3.10+, установка зависимостей командой python -m pip install -r requirements.txt. Скопировать .env.example в .env и указать свой OPENROUTER_API_KEY.

Команда: python main.py "Товар хороший, но доставили на неделю позже."

Для Workflow: python main.py --workflow "Товар хороший, но доставили на неделю позже."

One-shot делает один LLM-вызов, Workflow - два. Итоговые поля одинаковые. Проверяются JSON, поля и их типы на каждом этапе. При пустом отзыве, некорректном ответе или ошибке API обработка останавливается с сообщением об ошибке. Если первый этап завершился с ошибкой, второй не запускается.

Сравнение: python main.py --test. В main.py заданы 10 отзывов с эталонной тональностью и проблемами, включая сарказм, отрицание и инструкцию внутри отзыва (примеры 8–10). Ответы, время, число вызовов и токены сохраняются в results.json. Порядок запуска вариантов чередуется. Паузы между запусками не входят во время обработки.

Качество оценивается по accuracy тональности на всех 10 примерах; ошибка выполнения считается неверным ответом. Успех означает получение JSON с нужными полями и типами. Проблемы и ответы дополнительно проверяются вручную: проблемы соответствуют отзыву без пропусков и выдумок; ответ учитывает жалобы, не содержит выдуманных фактов и обещаний, занимает 1–2 предложения. Токены берутся из usage.total_tokens и суммируются по этапам. Если расход неизвестен, среднее число токенов не вычисляется.

Результаты одного прогона (One-shot / Workflow):
Успешные выполнения: 100% / 100%.
Accuracy тональности: 90% / 90%.
Среднее время, с: 1.961 / 2.209.
Среднее число LLM-вызовов: 1 / 2.
Средний расход токенов: 271 / 393.

В примере 2 One-shot предлагает оформить гарантийный случай без информации о гарантии, а Workflow просто направляет в поддержку. В примере 5 наоборот: Workflow предлагает обмен без заданных условий, One-shot этого не делает. В примере 7 оба варианта без достаточных данных подтверждают совместимость кабеля. В примере 8 оба ставят mixed вместо negative и пропускают жалобу на ожидание доставки: саркастическая похвала воспринята буквально. Accuracy отражает только тональность, а не правильность всего ответа.
